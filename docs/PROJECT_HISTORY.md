# 项目历程：从旋钮直调到 R7

[English](PROJECT_HISTORY.en.md) · [返回首页](../README.md)

本记录整理截至 2026-10-09 的工程成果。按依赖关系和修订顺序叙述；不为缺少独立时间戳的早期步骤补造日期。这里区分需求、代码实现、离线验证、用户实机反馈与仍未解决的事项。

## 1. 最初只想省掉一次 SET

原始目标很小：在普通机顶主界面，旋钮直接调整 TTL 曝光补偿或 M 功率，避免“先移动焦点、再按 SET、再调节”。TTL 的目标是 FEC，范围 ±3 EV、步进 1/3 EV；不是自行决定 TTL 闪光能量。

项目同时要求保留菜单、MODE、ZOOM、无线组、锁屏和其他设置的原行为，保留触摸与 SET，并尽量复用原厂边界、步进、加速及同步逻辑。因此研究起点不是全局改编码器，也不是重新实现功率数学，而是找到“进入编辑状态之后，原厂究竟调用哪段代码”。

初始对象包括 V100F 和 V480F。先保存原件、记录摘要，分析封装、架构与状态机；后续功能重心转为 V100F。公开版不会把这个演进误写成“两款已全面支持”。

## 2. 先证明固件是什么

两个样本都能识别到小端 ARM M-profile / Thumb-2 主应用和向量表，主应用映射到 `0x08008000`。Cortex-M4 / GD32F4xx 家族判断有较强证据，但具体芯片型号仍是推定。

V100F 原件为 1,002,732 字节，V480F 为 753,705 字节。两者包含相同的 19,692 字节辅助负载，启动和 UI 结构也有相似之处，支持来自共同框架的判断。但 V480 样本带有负载 MD5、文件名、长度及固定尾标记；V100 样本没有相同尾部。共同框架不意味着封装、偏移或校验可互换。

启动数据中确认了局部压缩初始化内容，不是整个镜像都被压缩或加密。辅助负载有自己的向量表，也有外围传输证据，但不能据此认定它是能救回主应用的恢复 bootloader。V100 的设备端完整性校验与签名覆盖范围没有确证。

这一步排除了“沿用别的 Godox 型号偏移”“看见辅助程序就认定能救砖”等捷径。详见[原生架构](native/ARCHITECTURE.md)。

## 3. 从参数函数到可观测的电脑工作台

为缩短调试反馈周期，项目建立了浏览器工作台：用 Unicorn 执行选定原厂参数函数，电脑端提供页面、输入、内存观察、调用日志和会话回放。

它逐步覆盖 Wi-Off、Sender、Receiver、TTL/M/Multi、菜单、组过滤和设置记录。26 项自动测试覆盖了模式边界、会话兼容和 HTTP 保存恢复等行为。它的价值是看清参数与调用，而不是假装拥有真实电容、闪光管、射频或完整 RTOS。

工作台的页面控制由适配层提供；原生固件的控件、回调、内存和中断约束还需要单独处理。两者一直是不同层级的工具。公开仓库早期只包含这一工作台，本次发布补上原生工程。

## 4. 原生直调与作用域收紧

原生补丁复用原厂调整函数，并以页面、模式和 UI 状态限制入口。后来需求扩展到 Receiver：在机顶和从属主界面，旋钮只调整主灯对应参数，不再滑到其他控件。

最终 `fixed_main` 模块约 508 字节。它保留非目标页面的原路径，不改 Sender 的组导航。接收模式下，无线下发仍可更新主灯设置；本地直调不是屏蔽接收命令。

项目另外追踪了 RX 事件顺序与中断影响。离线 ISR 观测可以检查覆盖场景中的执行顺序，却无法独自证明硬件无线延迟“完全不变”。因此相关报告明确保留真实时序未解决的限制，没有用通过的离线计数代替示波器或相机实测。

## 5. SU-1 解锁与原生界面：能显示还不代表能闪

下一组需求是把原厂机顶模式的 SU-1 控制扩展到主控和从属界面。Sender 增加本机副灯行，Receiver 增加副灯入口，并复用原生弹窗和功率调整。

实机反馈很快暴露了两种独立问题：控件与 ZOOM 叠在一起，以及界面虽然已经出现，副灯却未参与发光。后续确认机顶原有副灯与 TEST 可以工作，问题集中在无线角色的路径限制。R2 整理 Receiver 布局；R3 追踪并扩展 TEST 路径。

这里的关键经验是：**UI 可操作、TEST 会亮、相机拍照会亮，是三件必须分别验证的事。** 仅放开 UI 的角色限制，并不会自动让快门和接收中断使用副灯。

## 6. R4：补齐普通快门 / RX 路径，研究未充好怎么办

用户随后反馈：副灯在 TEST 下会闪，真实拍照不闪；Receiver 收到无线触发时只有主灯闪。修订转向原厂真正的曝光入口。

R4 在已确认的普通曝光分支中复用原厂双灯发光机制：主灯使用原厂计算或无线命令指定的功率，副灯使用本地 UI 设定。副灯不是复制主灯的数值，也不是新增无线组。

与此同时，对原厂机顶 TEST、普通拍照和相关无线路径进行就绪追踪。在已覆盖路径中，不满足就绪条件的请求被跳过；没有发现“等充好再补发”的就绪等待循环。补丁不添加这种等待或缓存，因为错过曝光窗口之后再闪，不能替代本次曝光。

主控发出无线命令与本机决定是否发光是不同环节，未证实存在“所有接收灯都充好才一起放行”的网络屏障。该结论只覆盖追踪到的路径，不扩大成所有设备/模式的协议保证。

这一阶段也使副灯弹窗回到原厂机顶几何布局，减少文字和功率控件重叠。HSS、Multi、预闪测光没有被顺手扩大为新的副灯功能。

## 7. R5：主灯 OFF 时副灯独立，与界面风格统一

新的实机问题是主控 M=OFF 时副灯也停止。早期另一个“OFF 仍闪”的报告经澄清是实体 TEST 的行为；这次是曝光路径中本机主灯关断把副灯一起挡住，二者不能混为同一个 bug。

R5 为已确认的普通主控曝光分支增加副灯单独路径：保留原无线发送，主灯仍为 OFF；副灯满足原就绪条件并开启时按本地功率发光。没有全局取消 OFF，也没有让主灯偷闪。

UI 同时改为接近原生组行的灰色区域和功率控件。离线验证还发现切屏动画期间新旧两个屏幕并存会增加对象/堆压力，于是减少不需要的 slider/bar，并在已确认生命周期中检查归属、回收旧副灯对象。这些问题无法靠单次页面截图发现。

## 8. R6：从“看起来重叠”追到真实层级与触摸命中

Receiver 下拉快捷面板展开后，副灯标签仍覆盖在亮度条上。根因不只是坐标：原厂下拉对象先创建，新增副灯后来加入同一根节点，因而拥有更高绘制层级。

R6 通过原生对象顺序调整，把副灯放到当前页面的下拉面板之前；同时保护相关焦点状态，防止副灯重新出现时抢回输入。验证不仅检查对象位置，还执行实际命中测试：原先冲突的 `(380, 320)` 点应归亮度控件，而不是副灯。

这一修订增加 296 项层级/命中检查。它解决的是覆盖关系和输入归属，不改变 R5 的发光模块。

## 9. R7：三个方框为什么只改成一个 S

实机照片显示 Sender 副灯名称变成三个空框。此前字符串和矩形验证通过，却没有证明选定字体真的包含 S、U、B。

检查原生字体表后发现，使用的数字字体不含这些字形；另一个组标签字体也没有可用 S。R7 选择已确认包含 S 的原厂字体：Sender 使用 19×24 字形，Receiver 使用 9×11 字形，并将标签统一为单字母 **S**。

新增 37 项检查直接验证字形存在、非空和布局。R7 保持 R6/R5 发光代码一致；它没有因为文件名或界面改字而获得 TTL。R7 的正式身份由 SHA-256 确定，不能靠“最新”“new”或文件名中的 TTL 判断功能。

## 10. 副灯 TTL：研究有进展，功能尚未开启

最后一个研究问题是“能否直接套用主闪 TTL”。当前有界观测显示：主灯预闪/测光结果路径与副灯手动时长路径分开；改变测光输入可以改变主灯结果，而同一副灯 UI 设置仍得到固定时长。

所以复制主灯 TTL 输出最多形成随主灯变化的联动手动输出。要声称真正 TTL，至少需要让副灯参与预闪、建立副灯能量标定、正确处理测光结果与主曝光，再验证副灯就绪与两灯能量分配。主灯和副灯独立测光也没有已证实的双通道支持。

本次保留 90 项研究观测，不向 R7 注入未经验证的 TTL 路径。详见[副灯 TTL 研究](native/SU1_TTL_RESEARCH.md)。

## 11. 公开发布时做了什么

2026-10-09，将分散实验整理为可移植发布包：

1. 保留原电脑工作台，把旧说明移到专用目录，避免把电脑功能误写成固件功能。
2. 提取 R7 的 C、汇编和链接脚本；三段代码重新编译后与既有 R7 完全一致。
3. 建立严格版本补丁工具，可本地生成并验证 R7，也可对精确候选做文件级逆变换。原始输入永不覆盖。
4. 移除运行所需的个人绝对路径，将 R4/R5 对照镜像也改为从用户原件在内存中复现。
5. 重新执行公开可移植子集：9,399 项功能检查及 90 项 TTL 研究观测；另通过 10 项补丁工具测试、26 项工作台测试。
6. 保存历史 39,851 项工程检查结果，但明确其中一些 runner 尚未移植，且所有数量均不是物理硬件测试次数。
7. 首次源码发布提供中英文历程、功能矩阵、恢复限制、源码及报告；当时未附完整 BIN。之后按作者要求加入双型号 BIN 下载，见第 13 节。原件、用户会话和私人照片仍未上传。

## 12. 当前成果与下一阶段

当前得到的是**可复现、可审阅、限定具体原件的实验性 R7**：主屏旋钮直调、无线角色下原生副灯 UI、普通发光路径支持、主控主灯 OFF 时副灯独立，以及多轮 UI 修复。

仍需要真实设备完成主/副灯光能、相机曝光、无线时序、回电、热行为和长时间稳定性验证；可靠恢复路径也未建立。用户授权生成实验文件与这些工程证据是两件事。[Gate 与恢复状态](native/RECOVERY.md)保留这一边界。后续若扩展 TTL 或其他机型，应建立独立的证据和测试，不把 R7 的通过记录沿用过去。


## 13. 双机型公开与现成 BIN 下载

2026-10-09，作者进一步要求把 V480 项目并入公开仓库、提供两款现成 BIN，并明确两台设备都已刷入修改固件。项目扩展为双型号仓库，目前仅包含 V100F 与 V480F；最终名称见第 14 节。

V480 公开的是此前已交付的 **rotary-direct v2**：仅在 Wi-Off 主界面直接调 FEC/M 功率，保留 0.1/0.3 步进和原厂加速，其他页面包括 Sender/Receiver 回落原行为。它没有继承 V100 后续的 RX 直调与 SU-1 功能。源码、独立补丁工具、V480 MD5 尾部处理和验证报告一并发布。

为避免只上传一个无法复现的 BIN，V480 316 字节 helper 重新编译后与旧 v2 完全一致；公开版单独执行 V480 的 12,489 项功能、746 次普通通信中断插入和 1,386 项整镜像执行检查，并通过 10 项补丁工具测试。早期双型号 24,978 / 1,491 的总数仍作为历史材料，未冒充 V480 单独成绩。

V100 下载保持 R7 的原有 SHA，V480 下载保持 v2 的原有 SHA。本次是整理和公开交付，不是继续改发光逻辑。作者两台设备已刷入的反馈独立记录；由于未提供在机 SHA，不把这项反馈扩写成每个下载版本都完成全部硬件验收。
